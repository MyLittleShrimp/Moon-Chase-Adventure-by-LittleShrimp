# 开发说明

## 环境与命令

- Node.js 24 或更新版本；交付时使用 Node.js 24.14。
- `npm start`：启动静态预览，默认端口 4188。
- `npm test`：运行 48 项自动测试。
- 无 npm 第三方依赖、无构建过程。`dist/` 是可编辑的源码，不能加入忽略列表。
- 如果 4188 被其他项目占用，可通过环境变量 `PORT` 指定其他端口；Windows PowerShell 示例：`$env:PORT=4189`，再执行 `npm start`。

## 模块边界

`engine.js` 管理场景、行走区域、寻路、阶段及存档数据。`game.js` 管理主线流程、探索、角色对话、背包、回访、暂停、小游戏回调与结局。`world.js` 绘制场景、机器人、宝箱与剧情画面。

`rules.js` 提供不依赖 DOM 的小游戏规则，`puzzles.js` 负责交互界面与控制。题库在 `quiz.js`，讲解与资料链接保留在题目数据中。

方向键使用 Pointer Events，在按下时触发移动，兼容键盘及辅助点击，避免松手等待与重复触发。车阵拖拽保留按钮节点，通过 pointer capture 跟踪拖动；拖动时仅预览 transform，松手后按格提交，取消触摸时恢复原位。`trafficSlideLimits` 根据实际碰撞规则限制移动范围，拖动不会穿过车辆。一次拖动记录一次撤回，成绩累计实际移动格数。

`audio.js` 管理主主题先播、其余曲目随机轮换、静音与页面失焦暂停。`movies.js` 管理首帧封面、真实视频帧到达、暂停、跳过和完成回调。

## 本地检查工具

```bash
node tests/preview-server.js
```

测试服务器仅监听本机 4174。`http://localhost:4174/?stage=0` 可载入对应任务的测试存档，阶段范围 0–10。`/audit` 用于场景检查；`/media-audit` 用于媒体检查；`/puzzle-audit` 可以直接检查三种方向控制小游戏，不读写玩家存档。这些页面用于开发，不在 `dist/` 中。

测试存档使用 4174 的独立网站存储，不会修改 4188 的正常试玩存档。不要在部署目录中加入测试服务器或调试页面。

## 视频与音乐

两段动画为 H.264 / AAC MP4，使用 faststart，约 1.73 MB 与 1.65 MB。首帧是独立 WebP；替换视频时同步替换对应封面，并保留纵向构图。`static-server.js` 支持字节范围请求，可验证视频分段读取。

音乐和音效文件名见 `audio.js`，动画文件名见 `movies.js`。不要只更新文件而漏改代码引用。建议保留用户原始素材的独立备份，仓库只收录实际运行所需版本。

## 部署

将 `dist/` 的内容作为静态网站根目录。游戏不需要数据库、登录接口或服务器业务逻辑。请保留素材子目录，支持 JS Modules 与正确媒体 MIME 类型；正式域名建议使用 HTTPS。

发布后检查：首次进入、动画载入与跳过、八种挑战、手机操作、静音与失焦、存档恢复、分支结局及隐藏收集。宣传片和截图位于 `docs/media/`，无需一起部署到游戏网站。

手机启动、图片超时与管线绘制的维护说明见 [手机兼容性记录](MOBILE_COMPATIBILITY.md)。启动入口是 `boot.js`，地图由 `images.js` 按需加载。
